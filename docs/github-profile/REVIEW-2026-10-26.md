Дата проверки: 26 октября 2026 года. Профиль: https://github.com/Vremennobeznika.

## Что проверено

Через подключение GitHub прочитаны метаданные семи публичных репозиториев, их README и списки файлов. В пяти проектах подтверждено наличие файлов скриншотов. После сохранения повторно прочитаны все пять изменённых README и каталог новых скриншотов.

Это проверка оформления и документации, а не полный аудит кода, доступности, безопасности или всех пользовательских сценариев. Публичные демо по HTTPS в этой сессии не открывались. Флаг has_pages подтверждает включённый Pages, но не успешность последнего развёртывания. Существование изображения не доказывает актуальность изображённого интерфейса.

## Что исправить в прежних рекомендациях

1. The Butler нельзя без проверки называть копией: в README описаны панель «Сегодня», пауза уведомлений, бытовые шаблоны и Mac LaunchAgent. Два похожих проекта допустимы, когда различие видно сразу.
2. prorab нельзя автоматически считать бесполезным: это опубликованный исходный архив с честным статусом незавершённой Windows-сборки. Главная проблема — неудобство просмотра кода и отсутствие проверенного установщика. Не закреплять в первой тройке до готовности; скрывать репозиторий необязательно.
3. PWA требует безопасного контекста для Service Worker: обычно HTTPS, а при локальной разработке подходит localhost. Выключенный Pages не означает, что приложение невозможно запустить. Установка PWA не гарантирует фоновые напоминания при закрытом браузере.
4. «README со скриншотами есть» не означает «проект готов». В профиль не стоит переносить обещание «всё доведено до рабочего состояния».
5. Bio «Ambassador of enjineering» в этой проверке не подтверждено. Если строка ещё используется, engineering — обычное английское написание; enjineering может быть намеренной отсылкой к названию бренда. Для найма полезнее конкретно назвать направление работы.
6. Срок «всё за час-полтора» не подтверждён: публикация, проверка PWA на устройстве и доведение Windows-проекта занимают разное время.

## Приоритет 3: доказательства качества

- Для каждого главного проекта опишите одну реальную задачу, своё решение и проверяемый результат. Не придумывайте метрики, аудиторию и коммерческие заказы.
- Для проектов с ИИ укажите фактическое распределение работы: что делали с помощью инструмента, что проверяли самостоятельно и какие решения можете объяснить. Не переносите из черновика утверждение «все проекты построены с ИИ» без подтверждения.
- Проверьте клавиатурную навигацию, фокус, контраст, подписи кнопок и работу при увеличении масштаба. Наличие мобильного скриншота не заменяет проверку доступности.
- Перед публикацией PWA проверьте HTTPS, загрузку Service Worker и повторное открытие без сети после первой загрузки; отдельно — JSON-экспорт и восстановление в чистом профиле браузера. Не очищайте хранилище с важными данными без резервной копии.
- Запускайте уже существующие тесты по инструкциям репозиториев. Отделяйте результаты текущего запуска от исторических результатов в README.
- Выберите лицензию, если хотите разрешить повторное использование кода. Отдельно учтите права на тексты, изображения и справочные данные; лицензию автоматически не назначали.
- Для prorab следующий полезный шаг — выложить исходники из архива обычными файлами после проверки состава, затем добиться успешной Windows-сборки и проверки установки/запуска/удаления. Не включать Pages только ради наличия ссылки: это настольный проект.

## Критерий готовности витрины

Человек за минуту понимает направление работы, открывает один из трёх разных проектов, видит реальный интерфейс, воспроизводит небольшой сценарий и находит честное описание ограничений. Работоспособность HTTPS-демо и реальных мобильных устройств остаётся проверить отдельно.
